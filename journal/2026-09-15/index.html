    WSL 离线安装与 Miniconda 初始化记录¶

    今天主要处理了两个 Windows 开发环境问题：wsl --install 持续返回 403，以及安装 Miniconda 后普通 PowerShell 无法识别 conda。前者最终通过离线安装绕过下载链路，后者则通过初始化 PowerShell 的 shell 集成解决。

    WSL 安装持续返回 403¶

    问题现象¶

    在 Windows 上重新安装 WSL 时，直接执行：

    wsl --install

    命令返回：

    已禁止 (403)。

    当时 Windows 已开启 Clash Verge。为了绕过 Microsoft Store，又尝试：

    wsl --install --web-download -d Ubuntu

    结果仍然是 403。这说明问题不只发生在 Microsoft Store 下载路径上。

    代理排查¶

    先检查 WinHTTP 是否继承了 Windows 代理：

    netsh winhttp show proxy

    最初显示：

    直接访问（没有代理服务器）。

    这意味着 Windows 虽然开启了 Clash 系统代理，但 WinHTTP 没有使用它。于是执行：

    netsh winhttp import proxy source=ie
netsh winhttp show proxy

    此时能够看到 Clash 的本地代理地址：

    代理服务器: 127.0.0.1:7897

    随后又确认 Clash Verge 已开启系统代理与 TUN 模式，并临时从规则模式切换到全局模式。然而再次执行在线安装时仍然返回 403。

    这次排查只能说明 WinHTTP 已获得代理配置，却不能据此断定 WSL 的所有下载请求都正确经过代理，也不能排除下载源、节点或区域限制。继续反复修改代理的收益已经很低，因此改用离线安装。

    最终方案：离线安装 WSL 与 Ubuntu¶

    以下命令需要在管理员 PowerShell 中执行。

    1. 启用 WSL 和虚拟机平台功能：

      dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

    2. 重启 Windows。

    3. 从 microsoft/WSL Releases 下载与系统架构匹配的 WSL MSI 安装包，并手动安装。

    4. 安装完成后检查版本：

      wsl --version

      本次得到：

      WSL 版本: 2.7.14.0
内核版本: 6.18.33.2-2
WSLg 版本: 1.0.73.2

    5. 单独下载 Ubuntu 的 .wsl 镜像，再从本地文件安装。文件名和路径应替换为实际值：

      wsl --install --from-file "D:\Downloads\ubuntu-24.04.wsl" --name Ubuntu-24.04

    6. 检查发行版并启动：

      wsl -l -v
wsl -d Ubuntu-24.04

    能够进入类似下面的终端，即表示发行版已经可以正常使用：

    user@LAPTOP:~$

    本次真正起作用的不是继续调整代理，而是将在线安装链路拆成两部分：先用 MSI 安装 WSL 本体，再从本地 .wsl 镜像安装 Ubuntu。

    wsl --install / --web-download
                ↓ 持续 403
检查 WinHTTP、Clash 与 TUN
                ↓ 仍然 403
安装 WSL MSI
                ↓
下载 Ubuntu .wsl 镜像
                ↓
wsl --install --from-file
                ↓
安装成功

    localhost 代理警告¶

    Ubuntu 第一次启动时还出现了提示：

    wsl: 检测到 localhost 代理配置，但未镜像到 WSL。
NAT 模式下的 WSL 不支持 localhost 代理。

    这不是 Ubuntu 安装失败。它表示 Windows 上的 127.0.0.1:7897 与 WSL NAT 网络中的 127.0.0.1 不属于同一个网络环境，WSL 因而不能直接连接 Windows 的 localhost 代理。

    可以按照 2026-09-07 的 WSL 网络配置启用 mirrored networking、DNS tunneling 和自动代理。修改 .wslconfig 后，先保存 WSL 中的工作，再执行：

    wsl --shutdown

    重新启动发行版后配置才会生效。

    Miniconda 安装后 PowerShell 找不到 conda¶

    问题现象¶

    安装 Miniconda 后，普通 PowerShell 没有自动激活 base 环境，也无法直接使用 conda 命令；但 Anaconda PowerShell Prompt 中可以正常使用。

    解决方法¶

    在 Anaconda PowerShell Prompt 中执行一次：

    conda init powershell

    然后关闭并重新打开普通 PowerShell。conda init 会把 Conda 的 shell 初始化代码写入 PowerShell 配置，使后续会话能够识别 conda activate 等命令。

    如果只希望能够使用 Conda、但不希望每次打开 PowerShell 都自动进入 base，可以再执行：

    conda config --set auto_activate_base false

    小结¶

    • WSL 在线安装持续出现 403 时，应先确认错误发生在哪条下载链路；代理设置已经生效但问题仍存在时，可以直接采用 WSL MSI + Ubuntu .wsl 的离线方案。
    • localhost 代理警告描述的是 Windows 与 WSL NAT 的网络边界，不等于发行版安装失败。
    • Miniconda 安装完成不代表所有 shell 都已经接入 Conda；PowerShell 需要单独执行一次 conda init powershell。
