    从人类示范筛选到 Git 原生实验树：ReWeight 与 OpenResearch¶

    今天关注了两项与“筛选”有关的工作：ReWeight 在大量人类示范中筛选真正适合目标机器人的数据，OpenResearch 则把研究假设和实验分支组织成可追踪的 Git 树。一个管理训练数据，一个管理研究过程，背后都是同一个判断：规模扩大之后，更需要对“什么值得被保留”做出明确选择。

    ReWeight：人类数据并非越多越好¶

    论文：ReWeight: Leveraging Human Data for VLA Post-Training via Demonstration Retrieval and Sample Weighting

    项目主页 · arXiv:2609.13851

    机器人演示采集成本高，而第一视角的人类操作视频更容易获取。问题在于，人手与机械臂的外观、运动学和动作空间都不同。如果直接混合 human demonstrations 与 robot demonstrations，不相关的人类数据反而可能因为 cross-embodiment discrepancy 拉低策略性能。

    ReWeight 没有把所有人类数据等量加入训练，而是做了两层选择：

    1. Demonstration-level retrieval：学习结合 visual observation 与 future action 的跨本体 visuomotor representation，再通过 optimal transport 找出与目标机器人行为更相似的人类示范。
    2. Sample-level weighting：在被选中的示范内，根据跨本体差异调整样本权重；越接近目标机器人行为的样本，训练时的影响越大。
    大量人类示范 + 少量目标机器人示范
                    ↓
跨本体 visuomotor representation
                    ↓
optimal transport 检索相关示范
                    ↓
按 cross-embodiment discrepancy 加权
                    ↓
              VLA post-training

    在论文报告的八个仿真任务中，ReWeight 将 post-trained π₀.₅ 的平均成功率从仅使用机器人数据时的 39%、随机混合人机数据时的 44% 提高到 57%；四个真实任务的平均成功率为 68.8%。这个结果强调的不是“人类数据越多越好”，而是必须先判断哪些人类经验对目标机器人真正有用。

    OpenResearch：把研究过程组织成实验树¶

    项目主页 · GitHub

    OpenResearch 可以理解为面向科研的 Git + Experiment Manager + Coding Agent 框架。它将 baseline 作为根节点，将不同研究假设展开为实验分支；每个实验都有独立的 Git branch 和 worktree，并关联代码、运行日志、指标与结论。

    baseline
├── hypothesis A → 修改代码 → 运行实验 → 记录证据
├── hypothesis B → 修改代码 → 运行实验 → 记录证据
└── hypothesis C → 修改代码 → 运行实验 → 记录证据
                                      ↓
                              选择下一轮方向

    这种设计有三个直接优点：

    • 隔离性：不同 agent 在各自的 worktree 中工作，避免实验之间相互污染。
    • 可追踪性：每个结果都能回到具体的代码状态和实验节点，方便比较与复现。
    • 并行性：多个 agent 可以同时验证不同假设，不必共享同一个脆弱的工作目录。

    它把“提出假设 → 改代码 → 跑实验 → 检查证据 → 决定下一步”的循环显式化了。不过，实验组织得更自动并不等于结论自动可信；评估协议、对照设置和对失败结果的记录仍然需要严格约束。

    两种“选择机制”¶

    工作 需要筛选的对象 选择依据 目标
    ReWeight 人类 demonstration 与其中的样本 与目标机器人行为的跨本体相似度 减少无关人类数据对 VLA post-training 的干扰
    OpenResearch 研究假设与实验分支 实验日志、指标和节点间的证据 让后续研究决策可追踪、可并行、可复现

    今日结论¶

    ReWeight 解决的是“哪些外部数据值得学”，OpenResearch 解决的是“哪条实验路线值得继续”。它们都不把规模本身当作答案，而是通过显式表示、可比较证据和选择机制，让数据与实验更有效地服务于目标。
