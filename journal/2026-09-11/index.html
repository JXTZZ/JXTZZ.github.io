    从语义动作到对象交互：Show-Harness 与 ORION¶

    站内更新 2026-09-11VLM Agent对象图

    今天读到两篇可以放在一起思考的工作：Show-Harness 研究视觉语言模型应该怎样向机器人表达动作，ORION 则研究怎样从一段人类视频中提取可迁移的物体交互。它们都在感知与控制之间加入了中间表示，用来连接任务理解和实际执行。

    Show-Harness：模型与机器人之间需要怎样的接口¶

    Show-Harness: Just a VLM Agent Can Play Robots提供了一层语义动作接口。视觉语言模型（VLM）根据观测和指令，选择离散的语义动作单元；针对具体机器人设计的解释器，再把这些单元确定性地转换为底层动作。另见项目主页。

    视觉语言模型 → 语义动作 → 机器人本体对应的解释器 → 底层动作

    这项工作提出了一个值得检验的问题：机器人表现不足，有多少来自模型能力，有多少来自模型与控制系统之间的接口？作者展示了闭源 VLM 的零样本控制，也展示了小型开源 VLM 经低成本微调后的应用。

    接口设计改变了模型需要直接处理的决策空间。阅读这类方法时，我想进一步确认语义动作的粒度、参数和反馈频率：模型负责哪些物理决策，解释器又承担了多少几何与控制工作？

    ORION：从人类视频中保留哪些交互信息¶

    ORION 的论文题为 Vision-based Manipulation from Single Human Video with Open-World Object Graphs，详见完整阅读笔记与本地 PDF。

    人类视频没有机器人动作标签，人的手与机械臂也不共享关节空间。但当人与机器人完成同一任务时，操作对象、接触关系和物体运动，仍可能提供共同的描述方式。例如，要操作哪个物体，从哪里抓取，以及物体应沿什么路径到达目标。

    ORION 把这些信息组织成开放世界对象图（Open-World Object Graphs，OOGs）序列。图中记录任务物体、抓取点与夹爪状态、三维关键点或六自由度位姿轨迹，边则描述接触与归属关系。执行时，机器人匹配当前任务阶段，将演示轨迹适配到新的起终点，再优化为末端位姿动作。

    与 SPOT 放在一起看¶

    SPOT也使用物体运动连接人类演示与机器人执行，不过它采用更紧凑的物体位姿轨迹。三项工作的表示与执行方式可以这样对照：

    工作 输入 中间表示 怎样生成机器人动作
    Show-Harness 机器人观测与语言指令 离散语义动作 本体对应的解释器转换为局部控制
    SPOT 少量 RGB-D 人类演示 目标相对的六自由度物体轨迹 结合抓持关系转换为末端轨迹
    ORION 单条 RGB 或 RGB-D 视频 对象、接触、抓取与运动组成的图序列 图匹配、轨迹适配与位姿优化

    表示的取舍没有一个简单的优劣顺序。SPOT 的轨迹紧凑，但需要可靠的物体位姿；ORION 保留更多交互关系，也依赖更长的感知流程；Show-Harness 让模型选择语义动作，控制能力则受到动作集合与解释器的共同约束。

    只有 RGB，怎样得到三维轨迹¶

    ORION 吸引我的一点，是普通 RGB 视频也可以作为演示来源。它结合单目深度估计、物体网格生成和多组位姿假设，再通过 FoundationPose 的位姿优化恢复六自由度轨迹。

    因此，使用 RGB 视频仍然需要估计三维几何。数据采集门槛降低了，但深度、网格尺度与跟踪误差可能逐步传到控制端。判断这一流程是否可靠，需要看它在遮挡、尺度不确定和位姿丢失时怎样处理。

    接下来想验证的问题¶

    一个可以先做的小实验，是固定底层控制器，只改变模型输出动作的接口。用有限、可解释的语义动作集合训练小型 VLM，检查它能否稳定选对动作，并在执行偏离预期后重新决策。这样能更清楚地观察接口本身带来的影响。

    另一条线索是比较物体轨迹与对象图。在相同演示和控制器下，逐步加入接触关系、抓取点和阶段信息，观察空间泛化、长时序执行与失败恢复的变化。增加信息是否值得，要连同额外感知成本一起判断。

    还可以考虑从 RGB 视频恢复 SPOT 所需的物体轨迹：由 VLM 识别任务对象与语义，再由带几何约束的模块估计连续位姿。这是待验证的组合方向，需要先检查位姿恢复是否足够稳定。

    这几篇工作让我更想弄清：模型理解任务后，究竟应该保留哪些信息，才能把这种理解交给机器人执行？答案需要同时考虑任务结构、感知误差与具体机器人的能力。
