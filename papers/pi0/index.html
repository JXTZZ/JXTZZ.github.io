    π₀：用视觉语言模型和 Flow Matching 控制多种机器人¶

    论文：Physical Intelligence，arXiv:2410.24164v4，PDF 版本日期 2026-01-08。

    先记住三句话：

    1. π₀ 输入多张 RGB 图、语言命令和机器人关节状态，一次输出未来 50 步连续动作。
    2. PaliGemma 负责理解视觉和语言，新增的 action expert 负责生成精细动作。
    3. 大规模预训练让机器人见过更多状态，高质量后训练让它把某个任务做得更流畅。

    一、论文对应的 Task 是什么？¶

    1. 任务定义¶

    论文研究的是通用机器人控制：希望一个基础模型能够控制单臂、双臂和移动机器人，并完成从短技能到长时程操作的多种任务。

    代表性任务包括：

    场景 机器人需要完成什么
    Shirt Folding 折叠摊平的 T-shirt
    Table Bussing 区分垃圾和餐具，放入不同容器
    Grocery Bagging 把不同形状的商品依次装袋
    Laundry Folding 从随机皱褶状态拿出多件衣物并折好
    Box Building 双臂折叠并组装纸盒
    Packing Eggs 把 6 枚鸡蛋放进蛋盒并关盒
    Mobile Laundry 移动双臂机器人边移动边整理衣物

    长任务可能持续 5–20 分钟，并包含抓取、分类、堆叠、折叠、压平和失败重试等许多子行为（Figure 1；Figure 12，p. 11）。

    2. 实际任务的输入¶

    机器人在每次决策时获得：

    • 2 或 3 张当前 RGB 图像，例如腕部和外部相机；
    • 一句语言命令，例如“bus the table”；
    • 当前关节角向量 q_t。

    部分复杂任务还可以由上层 VLM 把大目标拆成文字子命令，例如：

    “清理桌面”
↓
“拿起餐巾”
↓
“把餐巾扔进垃圾桶”

    这个上层 VLM 是可选的系统组件，不是 π₀ 内部自己输出的动作规划器。论文没有说明它的具体型号和 prompt。

    π₀ 的标准输入不含深度、点云、触觉、力反馈或显式历史窗口。

    3. 实际任务的输出¶

    π₀ 一次生成未来 50 步连续动作：

    A_t = [a_t, a_{t+1}, ..., a_{t+49}]

    不同机器人动作维度不同。模型内部统一补零到 18 维，因此输出 tensor 是 50×18；真正执行时只取该机器人对应的有效维度（Section IV，p. 4；Section V-C，p. 6）。

    它不会始终执行完 50 步：

    • 20 Hz 的 UR5e/Franka：执行前 16 步，即 0.8 秒；
    • 50 Hz 的其它机器人：执行前 25 步，即 0.5 秒；
    • 然后重新观察并生成新动作块（Appendix D，p. 16）。

    论文给出了动作维度，但没有统一说明每一维是绝对位置、增量、速度还是其它控制量。

    4. 为什么值得研究？¶

    通用机器人同时面临三个难题：

    1. 语义问题：清桌时要知道哪些是垃圾、哪些是餐具。
    2. 控制问题：折衣、装蛋等任务需要高频、连续、双臂协调动作。
    3. 数据问题：少量高质量演示能教会固定流程，却很难覆盖抓取失败、物体滑落和异常初态。

    π₀ 希望把 VLM 的语义知识、生成式连续控制和大规模多机器人数据结合起来。

    一句话 Task：给定多视角 RGB、语言目标和机器人当前关节状态，生成未来连续动作块并周期性重规划，使多种机器人完成精细、长时程操作。

    二、这个任务有哪些数据集，本文用了什么数据？¶

    1. 预训练数据¶

    作者把自采数据与开源数据混合训练：

    • 自采 π dataset：903M timesteps；
    • 其中 106M 来自单臂，797M 来自双臂；
    • 覆盖 7 种机器人配置和 68 个宽任务；
    • 论文把总体规模概括为超过 10,000 小时；
    • 开源数据占训练采样权重的 9.1%，包括 OXE/OXE Magic Soup、Bridge v2 和 DROID（Section V-A，p. 5；Figure 4）。

    这里的“68 个任务”不是 68 个简单“动词+物体”。例如 bussing 算一个任务，但里面已经包含许多餐具、垃圾、遮挡和分类行为。

    论文 Section III 一处写“entire OXE”，Figure 4 和 Section V-A 又明确写“OXE subset/OXE Magic Soup”。两处不一致，汇报时应采用更具体的“使用 OXE 子集”。

    2. 数据怎样平衡？¶

    不同机器人数据量差异很大。作者把每个“任务—机器人”组合的样本量记为 n，采样权重设为：

    weight ∝ n^0.43

    指数小于 1，因此数据越多，权重仍增加，但不会按原始数量线性增长。Figure 4 中，Bimanual ARX 约占原始步数 51%，训练权重降到约 34.2%。

    状态和动作统一补到 18 维；相机最多 3 个，缺少的相机槽被 mask。

    3. 后训练数据¶

    预训练数据强调任务和状态多样性，质量可以不完全一致。后训练数据则要求动作流畅、执行策略一致。

    • 简单任务可能使用约 5 小时；
    • 最复杂任务超过 100 小时；
    • 数据量实验使用 1、5、10 小时子集（Section V-A，p. 5；Figure 11，p. 10）。

    论文没有系统说明遥操作设备、操作者数量、失败轨迹比例、筛选标准、标注一致性和训练/验证 episode 划分。

    4. 一条原始数据包含什么？¶

    以 50 Hz 双臂 ARX 的折衣轨迹为例：

    episode = {
  rgb:       [T, 3, H, W, 3],
  q:         [T, 14],
  action:    [T, 14],
  task_text: "fold the shirt",
  segment_text: 约2秒片段的细粒度文字标注
}

    从这条轨迹在时刻 t 取出的训练 sample 是：

    o_t = {
  当前3张RGB,
  当前语言,
  当前14维q_t → 补到18维
}

target = 未来50个动作
         原始50×14 → 补到50×18

    训练时还会加入随机噪声和 flow timestep。它们是算法产生的变量，不是原始数据字段。

    图像分辨率、action normalization、轨迹末尾不足 50 步怎样处理，论文中未明确说明。

    三、已有工作怎样解决这个 Task？¶

    1. OpenVLA¶

    OpenVLA 是 7B VLA，把连续动作离散成 token，再按顺序生成。它有较强语义能力，但不支持 action chunk，也不适合 20–50 Hz 高频动作。

    在双臂折衣或复杂清桌中，机器人需要连续协调多关节。逐 token 生成既有量化误差，也增加延迟。Figure 7 中 OpenVLA 在五个 out-of-box 任务上大多接近零。

    2. Octo¶

    Octo 是 93M 通用机器人策略，可以用 diffusion 生成连续动作。它解决了连续动作形式，但模型容量和开放语言语义较弱。

    当任务要求识别新物品、按语言分类垃圾与餐具时，仅有连续动作生成还不够。Figure 7 中 Octo 同样接近零。

    3. π₀-small¶

    π₀-small 是 470M 非 VLM 对照。它用 DistilBERT 处理语言、较小视觉 encoder 处理图像，也用 10 步 flow matching 生成 50 步动作。

    Figure 9 中，它在 bussing、grocery bagging 和 table setting 的语言跟随准确率明显低于完整 π₀。即使上层 VLM 给出子命令，它也未必能可靠执行。

    但这个对照同时改变了参数量、语言模型、视觉模型和 transformer 结构，因此不能把全部差距只归因于“有没有 VLM 预训练”。

    4. ACT 和 Diffusion Policy¶

    它们从目标任务数据单独训练，是精细操作中的强基线。

    问题在于，小规模高质量演示通常只覆盖正确流程。遇到随机皱衣、遮挡或抓取失败后，策略可能不知道怎样恢复。π₀ 用大规模预训练补充这些多样状态，再用后训练学习流畅策略。

    四、本文方案有什么特点和创新？¶

    Baseline 的问题 π₀ 的设计 为什么有帮助 证据
    VLM 语义与连续控制难统一 VLM expert + action expert 一套权重理解图文，另一套专门处理状态和动作 Fig. 3、Fig. 9
    离散单步动作慢且不连续 对 50 步动作做 flow matching 联合生成连续动作块，避免动作 token 量化 Fig. 7、Table I
    多机器人输入输出维度不同 3 相机槽、18 维 padding 一个模型可以共享跨平台数据 Fig. 4–5
    大数据源支配训练 n^0.43 重采样 保留大数据价值，同时提高小任务出现概率 Fig. 4
    预训练不够熟练，scratch 又脆弱 多样预训练 + 高质量后训练 前者学覆盖和恢复，后者学一致执行流程 Fig. 11、13

    五、本文的具体方案¶

    1. 整体流程¶

    大规模多机器人数据
↓ 预训练
通用 π₀ 基础策略
↓ 目标任务高质量数据后训练
熟练的任务策略

部署时：
2/3张RGB + 语言 + q_t
↓ 双专家 Transformer
从随机噪声生成未来50步动作
↓ 执行前16或25步
重新观察，再次生成

    它是离线模仿学习，不是 RL；action chunk 一次联合生成，不是按时间自回归。

    2. 双专家结构是什么？¶

    主模型以 PaliGemma 3B 为基础：

    • VLM expert：处理图像和语言，继承互联网视觉语言预训练；
    • action expert：处理关节状态和带噪动作，从头训练，约 300M 参数；
    • 总参数约 3.3B（Figure 3；Section IV，pp. 3–4）。

    这里的“专家”不是传统 MoE 的动态选择。token 类型已经决定走哪套权重：图像/语言走 VLM，状态/动作走 action expert。两者通过 self-attention 交换信息。

    action expert 更窄，hidden width 为 1024，MLP 为 4096；VLM width 为 2048。这样做可以减少 10 次 flow 推理的计算量（Appendix B，p. 15）。

    3. 输入 token 怎样组织？¶

    输入分成三个 block：

    Block 1：[图像patch tokens + 语言tokens]
Block 2：[机器人状态q token]
Block 3：[50个带噪action tokens]

    attention 规则是：

    • 图像和语言只看图像/语言；
    • q 可以看图像、语言和自身；
    • action 可以看全部观察，也可以看其它所有 action slots。

    action block 内是双向 attention，因此 50 步动作可以共同协调。前面的 observation 不看 action，便于在 10 次 flow 迭代中缓存它的 key/value。

    4. Flow Matching 的直觉¶

    训练时有真实动作块 A。作者随机生成同样大小的高斯噪声 ε，再按 τ 混合：

    \[ A^\tau=\tau A+(1-\tau)\epsilon \]
    • τ=0：几乎是纯噪声；
    • τ=1：就是真实动作；
    • 中间值：噪声和真实动作的混合。

    模型不直接预测最终动作，也不预测噪声，而是预测“当前应该往哪个方向移动”：

    \[ v_{target}=A-\epsilon \]

    预测速度与真实速度之间计算 MSE。可以把它想成：训练模型学习一张导航地图，让随机动作沿着正确方向流向专家动作。

    作者让训练更多采样低 τ、高噪声区域，因为从几乎随机的动作中根据观察恢复合理动作更困难（Appendix B/Figure 14，p. 15）。但论文没有与 uniform timestep 做性能消融。

    5. 一个 batch 怎样训练？¶

    如果 batch size 是 B，逻辑形状为：

    RGB：       B组，每组2或3张图
language：  B条文本
q_t：       B×18
GT action： B×50×18

    训练步骤：

    1. 读取 observation 和未来 50 步专家动作。
    2. 采样 τ 和高斯噪声 ε。
    3. 构造带噪动作 A^τ。
    4. 双专家 transformer 输出 50×18 的速度场。
    5. 与目标 A−ε 计算 MSE。
    6. 反向传播更新模型。

    full π₀ 预训练 700k steps；为了和基线近似算力公平，作者还训练了 160k-step π₀。batch size、optimizer、学习率和后训练 steps 未明确说明。

    论文把概率路径写成 N(τA,(1−τ)I)，但采样式对应的协方差应是 (1−τ)^2I。若第二项表示标准差则没有矛盾；若表示协方差则记号不一致。论文未澄清。

    6. 推理怎样运行？¶

    当前观察编码一次，并缓存KV
↓
随机初始化 A^0，shape=50×18
↓ 10次
A^(τ+0.1) = A^τ + 0.1 × 模型预测速度
↓
得到 A^1，即50步动作块
↓
裁掉无效padding维并执行前一部分

    RTX 4090、3 相机下的时间为（Appendix Table I，p. 16）：

    部分 时间
    图像编码 14 ms
    observation forward 32 ms
    10 次 action flow 27 ms
    onboard 总计 73 ms
    加 Wi-Fi 的 offboard 总计 86 ms

    模型不是每个 20 ms 都推理一次，而是预测较长动作块，每 0.5 或 0.8 秒更新一次。

    7. 用一条折衣数据走完整流程¶

    原始时刻：3张RGB + 14维q + 未来50×14专家动作
↓ 跨机器人标准化
3张RGB + 18维q + 50×18动作
↓ 训练时加入τ和噪声
50个带噪action tokens
↓ VLM/action双专家
预测50×18速度场
↓ 与A-ε计算MSE

    部署时则从 50×18 随机噪声开始，做 10 次 Euler 更新，取前 14 个有效维度。ARX 以 50 Hz 执行前 25 步，也就是 0.5 秒，再根据新的衣物形态重新规划。

    六、本文效果如何？¶

    1. Out-of-box 基础模型¶

    作者在 5 个预训练中出现过的宽任务上直接测试，每个方法每任务 10 次。下表是根据 Figure 7（p. 8）人工读图的近似值：

    方法 折衣 简单清桌 困难清桌 杂货装袋 取吐司
    π₀ full 1.00 0.97 0.89 0.79 0.75
    π₀ 160k 0.90 0.82 0.50 0.34 0.40
    π₀-small 0.50 0.44 0.33 0.27 接近 0
    OpenVLA / Octo 多数接近 0 低 接近 0 接近 0 接近 0

    这些任务并非全新任务，因此更准确的说法是“预训练后无需专门微调即可调用”，而不是严格的 zero-shot 新任务泛化。

    2. 语言跟随¶

    Figure 9 左侧人工读图约为：

    任务 π₀-small π₀
    Bussing 0.70 0.95
    Grocery Bagging 0.32 0.70
    Table Setting 0.31 0.90

    完整 π₀ 更能听懂语言。上层 VLM 子命令也能提高 π₀ 的任务进度；π₀-small 因低层 grounding 不可靠，未能稳定利用上层命令（Section VI-B，pp. 8–9）。

    3. 1、5、10 小时后训练¶

    Figure 11（p. 10）显示：

    • 五任务平均：π₀ 约为 0.56/0.84/0.85；scratch 约为 0.38/0.76/0.72。
    • Towel Folding 和 Stack Bowls 的预训练收益明显。
    • Items in Drawer 在 5/10h 时 π₀ 与 scratch 都约 0.9，预训练几乎没有额外收益。
    • Tupperware in Microwave 的部分数据量点，scratch 或任务专用 baseline 与 π₀ 接近甚至略高。

    所以结论应是：预训练经常提高小数据效率，尤其当新任务与旧技能相似；它不是在所有任务都必然有益。

    5. 实验真正证明了什么？¶

    证据较强：

    • 完整系统比 OpenVLA、Octo 和 π₀-small 更适合这些高频复杂任务；
    • 预训练与后训练通常缺一不可；
    • VLM 路线改善语言跟随；
    • 700k steps 显著好于 160k，训练规模重要。

    仍未单独证明：

    • 双 expert 是否优于相同参数的单 expert；
    • flow matching 是否优于相同 backbone 的 diffusion/regression；
    • shifted-beta 是否优于 uniform；
    • n^0.43 是否是最佳采样指数；
    • 50 步 chunk 和 10 次积分是否最优。

    因此最稳妥的结论是“完整 recipe 有效”，而不是每个组件都已有严格因果证据。

    七、论文的不足和改进方向¶

    1. 作者明确指出的不足¶

    1. 不知道怎样选择最优数据混合和采样权重。
    2. 并非所有任务都能稳定完成，也无法预先判断需要多少后训练数据。
    3. 跨任务、跨机器人何时正迁移仍不清楚。
    4. 没有验证驾驶、导航和足式运动等其它控制领域。
    5. 只用高质量目标数据会脆弱，只用预训练又不够流畅。

    2. 我们还应注意什么？¶

    • 903M timestep 大多是私有数据，采集和筛选过程不透明，外部难复现。
    • 没有明确 validation split，也没有完整 held-out 物体/环境清单。
    • 每组通常只有 10 次测试，没有误差条或显著性检验。
    • π₀-small 同时改变模型大小和多项结构，不是干净的 VLM 消融。
    • OpenVLA/Octo 没有训练到 full π₀ 相同 epoch，公平性有限。
    • 3.3B 模型仍依赖高端 GPU，Wi-Fi 尾延迟和断网策略未评估。
    • chunk 内仍开环 0.5/0.8 秒，环境突然变化时不能立刻响应。
    • 没有系统报告碰撞、夹持力、人工接管和安全停止。

    3. 可以怎样改进？¶

    现有问题 改进思路 怎样验证
    数据混合靠经验，可能负迁移 根据技能相似度和梯度冲突学习数据权重 固定算力，测试完全未见任务/机器人
    组件贡献混在一起 同 backbone 比较 regression、DDPM、flow 同时报告成功率、动作平滑和推理次数
    固定执行 16/25 步反应不够快 用生成不确定性决定何时提前重规划 中途移动物体、制造滑落和碰撞风险
    单帧视觉无法判断接触 加短历史、触觉和力信息 构造视觉相同但接触状态不同的场景
    上层 VLM 可能给错子目标 为子目标加入前置条件、安全检查和拒绝机制 注入错误、含糊或不可执行命令

    汇报时最值得讲的 3 个点¶

    1. 双专家如何分工。 PaliGemma 保留视觉语言知识，较小 action expert 专门建模连续动作，两者通过 attention 交流。
    2. Flow Matching 到底预测什么。 输入带噪动作，输出从噪声走向专家动作的速度 A−ε；推理从纯噪声做 10 次 Euler。
    3. 预训练和后训练各解决什么。 预训练提供多样状态与恢复能力，后训练提供稳定、流畅的目标任务策略。

    常见问题¶

    Q1：π₀ 输出一个动作还是一段动作？¶

    一段未来 50 步动作。实际只执行前 16 或 25 步，再重新观察。

    Q2：它是自回归模型吗？¶

    语言 backbone 来自自回归 VLM，但 50 个动作位置不是按时间逐个生成，而是在 flow 中联合更新。

    Q3：Flow Matching 和 Diffusion 有什么关系？¶

    都从噪声生成数据。π₀ 学的是连续路径上的速度场，并用 ODE/Euler 积分；传统 DDPM 常预测噪声并按离散反向过程采样。

    Q4：为什么 action token 可以互相看见未来位置？¶

    测试时所有 action slots 都从噪声开始，并没有真实未来动作可以偷看。双向 attention 只是让整段动作共同协调。

    Q5：Figure 7 是真正的新任务 zero-shot 吗？¶

    不是。任务类型存在于预训练中，它主要证明无需任务专门后训练的直接调用和初态/物体泛化。

    Q6：预训练一定有帮助吗？¶

    不一定。Items in Drawer 几乎无增益，Packing Eggs 的 scratch 还略高。迁移取决于任务和平台相似性。

    附录：术语表¶

    • Action Expert：专门处理机器人状态和连续动作 token 的 transformer 权重。
    • Flow Matching：学习一个速度场，把随机噪声连续变换成数据样本。
    • Vector Field（向量场）：在当前 noisy action 上，模型预测下一步应该往哪个方向移动。
    • Euler Integration：按“小步前进 = 当前值 + 步长×速度”重复更新。
    • Action Chunk：一次生成多个未来动作。
    • Open-loop Chunk：执行动作块内部时不重新调用模型。
    • Closed-loop/Receding Horizon：执行一部分后重新观察并规划。
    • Padding：给低维状态或动作末尾补零，使不同机器人具有相同输入形状。
    • Language Grounding：把语言中的对象和目标对应到当前场景和动作。
    • Pre-training / Post-training：先用多样大数据学通用能力，再用高质量目标数据学熟练策略。
