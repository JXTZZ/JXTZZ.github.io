# ReWeight 与 OpenResearch 阅读记录

今天读到的两项工作，分别处理训练数据与研究过程：ReWeight 研究哪些人类示范适合帮助机器人学习，OpenResearch 则帮助记录实验及其证据。它们让我想到，数据和实验越来越多以后，怎样判断下一步该用什么、该继续做什么，也会成为实际问题。

## ReWeight：哪些人类示范对目标机器人有帮助

[ReWeight](https://arxiv.org/abs/2609.13851)尝试将人类示范用于视觉—语言—动作模型的后训练。人类第一视角视频容易获得，但人手与机械臂的形态、运动学和动作空间不同，直接混合人类与机器人数据，未必能够改善策略。另见[项目主页](https://reweight-vla.github.io/)。

它分两步使用人类数据。首先，学习结合视觉观测与未来动作的跨本体视觉运动表示，再用最优传输检索与目标机器人行为相关的人类示范。随后，在选中的示范内部，根据跨本体差异调整样本权重，让更相关的样本在训练中发挥更大作用。

```text
人类示范与目标机器人示范
            ↓
学习跨本体的视觉运动表示
            ↓
检索行为相关的人类示范
            ↓
按样本相关程度分配权重
            ↓
         策略后训练
```

论文在八个仿真任务上报告，后训练的 π₀.₅ 平均成功率从仅使用机器人数据时的 39%、随机混合人机数据时的 44%，提高到 57%；四个真实任务的平均成功率为 68.8%。这些数字来自作者的评估，本笔记没有复现实验。

我想继续弄清的是，检索与加权各自解决了多少问题：如果只选取相关示范是否已经足够？哪些任务更容易受到不相关人类数据的干扰？这些问题需要结合消融和失败案例来读。

## OpenResearch：让实验结果能回到具体证据

[OpenResearch](https://github.com/alphaXiv/OpenResearch)是用于研究代理的工作环境，提供实验记录、日志、代码与产物管理，支持代理根据已有结果继续研究。另见[项目主页](https://openresearch.sh/)。

我对这类工具的关注点，是每项结果能否对应到明确的假设、代码状态和运行条件。不同实验如果共用一个不断变化的目录，即使保留最终指标，也可能很难说清结果究竟来自哪一版实现。

一种容易理解的组织方式，是以基线为起点，为不同假设建立实验分支：

```text
基线
├── 假设 A → 修改代码 → 运行实验 → 记录证据
├── 假设 B → 修改代码 → 运行实验 → 记录证据
└── 假设 C → 修改代码 → 运行实验 → 记录证据
                                      ↓
                                决定下一轮实验
```

项目的[实验树说明](https://github.com/alphaXiv/OpenResearch/blob/main/agent-skills/orx-experiment-tree/SKILL.md)以基线为根节点，并为子实验建立 Git 分支。实验分支与代理会话使用的 worktree 是不同层次的组织方式，不能直接理解为每项实验必有一个独立 worktree。即使代码已隔离，数据、输出目录和计算资源仍需单独管理。

对我而言，值得借鉴的是记录习惯：保存基线、明确每次修改、关联日志与指标，并留下继续或停止某条路线的理由。自动运行实验之后，评估协议、对照条件和失败结果仍然需要检查。

## 留给后续阅读的问题

ReWeight 的筛选可以通过下游策略表现来检验；实验路线的选择则需要更多条件，包括比较是否公平、结果能否复现，以及失败是否说明假设有误。两者都需要证据，但不能把它们视为同一种算法机制。

接下来我想把这个习惯用到自己的实验中：加入一批数据或继续一条路线之前，先写清预期改善什么，再用固定评估检查变化。即使结果没有提升，也应留下足够信息，帮助下一次判断。
