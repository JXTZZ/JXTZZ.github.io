# 论文速记与 WSL 网络配置

## 有意思的文章

### DroneCATS

这篇文章探讨了一个基础问题：足够强大的 MLLM 是否已经具备足够的动作推理（action reasoning）能力，能够直接承担 VLA 的部分任务，从而减少重新训练大参数量 VLA 的需求？

实验中，作者没有对 MLLM 进行微调，也没有提供固定的 function-calling schema，而是通过 prompt 描述无人机的整个动作空间，让模型自主完成指令执行、接近目标、跟踪、搜索、偏航控制，以及判断是否到达目标等行为。

值得关注的是，这项工作尝试将 MLLM 已有的理解与推理能力直接用于动作决策。不过，能否进一步替代 VLA，还需要结合任务范围、控制精度和实时性要求来判断。

### MINERVA

这篇文章从一个小模型出发，审视 LIBERO benchmark 的评估有效性：一个仅有 0.45M 参数的模型就能达到 95.1% 的成功率，与 π0.5 相差不大。然而，打乱 task ID 后，模型表现接近随机；在 LIBERO-Plus 上，成功率也下降到 46%～56%。

这些结果提示，模型在标准 LIBERO 上取得高成功率，并不一定意味着它具备强大的泛化能力。模型可能利用了任务标识或固定环境中的规律，而没有真正学会适应环境变化。

因此，评估时除了关注标准测试集上的成功率，还应关注场景、光照等条件变化后的表现。相比固定条件下的高分，变化条件下能否保持稳定，更能反映模型的鲁棒性。

## 碰到的问题及解决方案

### WSL 无法正常执行 `git clone`

这次遇到的问题是：Windows 已连接代理，但 WSL 中的 `git clone` 仍无法正常访问远程仓库。原因可能是 WSL 没有正确使用 Windows 侧的代理配置。

本次采用的处理方式如下。

1. **检查代理软件设置**

    在 Windows 代理软件中开启“允许局域网连接”，使其能够接受来自 WSL 的连接。是否必须开启，取决于代理软件和 WSL 的网络模式。

2. **配置 WSL 网络**

    打开 Windows 用户目录中的 `.wslconfig` 文件；如果文件不存在，可以新建。在 PowerShell 中执行：

    ```
    notepad "$env:USERPROFILE\.wslconfig"
    ```

    写入以下内容。如果文件中已有配置，应合并到现有的 `[wsl2]` 段落中：

    ```
    [wsl2]
    networkingMode=mirrored
    dnsTunneling=true
    autoProxy=true
    ```

    这三个选项分别用于启用镜像网络模式、DNS 隧道，以及自动使用 Windows 的 HTTP 代理信息。

3. **重启 WSL，使配置生效**

    保存 WSL 中的工作后，在 PowerShell 中执行：

    ```
    wsl --shutdown
    ```

    然后重新打开 WSL，再尝试执行 `git clone`。


这是一项持久配置，通常不需要每次启动 WSL 时重复设置。不过，实际效果仍取决于 Windows、WSL 版本及代理软件配置；如果代理地址或端口发生变化，需要重新检查连接。
