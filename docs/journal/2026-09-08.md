# RoboSPA 与 Snipaste 自启排障

## 有意思的文章
### RoboSPA
一个新的benchmark，专门测试VLA的空间推理与长程规划，目前的VLA在复杂spatial relation、精细低层执行以及依赖历史记忆的任务上仍明显困难，即使在LIBERO这类benchmark上VLA已经达到了90%+的正确率，也并不意味着解决了真正的几何与长程操作问题。
## Snipaste 开机自启失效排查与修复记录

### 问题现象

Snipaste 已勾选“开机启动”和“以管理员身份”，但每次登录电脑后仍需手动启动。

程序路径：`D:\Tools\Snipaste\Snipaste.exe`

### 排查发现

1. 配置文件中确实开启了自启及管理员选项。

2. 启动文件夹中存在 `Snipaste.lnk`，指向正确程序，但使用的是 `-admin` 参数。

3. 当时未查到对应的高权限自启计划任务；受检查权限限制，这项结果不能单独证明任务绝对不存在。

4. Snipaste 日志显示 `Elevated: false`，说明被检查的实例实际没有管理员权限。


据此判断，原自启方式依赖普通启动快捷方式请求提权，未能可靠完成管理员启动。界面勾选不等于管理员自启已经生效。

### 修复过程中遇到的问题

最初生成的修复 EXE 后来在目录中消失，原因未确认，不能认定是安全软件删除。

随后提供的中文 PowerShell 脚本启动后闪退。实际复现发现：脚本使用无 BOM 的 UTF-8 编码，而启动器调用 Windows PowerShell 5.1，导致中文被错误解析，尚未请求 UAC 就发生语法错误。此前仅通过 PowerShell 7 语法检查，未覆盖实际运行环境。

修正方式：

- 改用纯英文内容的核心脚本及英文文件名，避免编码问题。

- 使用实际 Windows PowerShell 5.1 检查兼容性。

- 将需要系统权限的任务操作放到管理员提权之后。

- 保留终端窗口，并将执行结果写入日志，避免错误一闪而过。


### 最终修复方式

创建名为 `Snipaste Elevated Startup` 的 Windows 计划任务：

- 在指定用户登录时触发，延迟 15 秒。

- 以最高权限运行，仅在用户登录的交互会话中启动。

- 执行 `D:\Tools\Snipaste\Snipaste.exe`，工作目录设为程序所在文件夹。

- 允许电池供电时启动，不因切换电池而停止。

- 取消任务运行时限，避免常驻程序被定时结束。

- 已有任务实例运行时，不重复启动。


任务保存并核对后，将原启动文件夹中的 Snipaste 快捷方式移出并备份，避免两套启动方式同时触发。随后手动触发新任务，确认 Snipaste 成功启动。

### 修复结果与验证范围

用户运行新版启动器并确认 UAC 后，日志显示：

- 管理员权限获取成功。

- 最高权限登录任务已保存并核对。

- 原启动快捷方式已备份。

- Snipaste 已通过新任务启动。

- 自启配置修复完成。


**已完成配置修复及即时启动测试；重启或注销后能否自动启动，仍需实际登录验证。**

验证方法：保存工作并重启电脑，登录后等待约 15～30 秒，确认托盘出现 Snipaste，且截图快捷键可用。

### 文件留存

修复文件位于：

`%USERPROFILE%\Documents\Snipaste-Fix\outputs（示例路径）`

- `Run-Snipaste-Fix.cmd`：修复启动器。

- `Fix-Snipaste.ps1`：核心修复脚本。

- `Snipaste-startup-fix-result.txt`：执行日志。

- `Snipaste-startup-backup-*.lnk`：原启动快捷方式备份。


正常使用无需重复运行修复脚本。若以后移动 Snipaste 程序目录，需要同步更新计划任务的程序路径和工作目录。
