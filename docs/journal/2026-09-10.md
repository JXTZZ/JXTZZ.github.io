# Python 堆与 heapq：怎样维护当前最值

处理第 K 大、优先级队列或数据流时，我们常常只关心当前最小或最大的元素。每来一个新元素就重新排序，会做许多暂时用不到的工作。堆适合维护这种不断变化的候选集合。

## 堆保证了什么

这里讨论的是二叉堆。它在结构上是一棵完全二叉树，在数值上满足父子节点之间的约束：最小堆的父节点不大于子节点，最大堆则相反。因此，堆顶就是当前最小值或最大值。

但堆并不是有序数组。同一层的节点之间没有完整的大小顺序；按数组下标遍历，也不会直接得到排序结果。

Python 的 `heapq` 使用列表保存二叉堆。对下标为 `i` 的节点，左右孩子的下标分别为 `2 * i + 1` 和 `2 * i + 2`；非根节点的父节点下标为 `(i - 1) // 2`。

## 从最小堆开始

不带 `_max` 后缀的接口维护最小堆：

```python
import heapq

heap = [8, 2, 5]
heapq.heapify(heap)           # 原地建堆
heapq.heappush(heap, 3)       # 加入元素，保持堆的约束
print(heap[0])               # 2，只查看堆顶
print(heapq.heappop(heap))   # 2，取出并删除堆顶
```

查看和弹出堆顶都要求堆非空。几个常用操作的复杂度如下：

| 操作 | 时间复杂度 |
| --- | --- |
| 查看 `heap[0]` | $O(1)$ |
| `heapify()` 原地建堆 | $O(n)$ |
| `heappush()` 插入 | $O(\log n)$，不计列表偶发扩容的单次开销 |
| `heappop()` 弹出堆顶 | $O(\log n)$ |

### `heappushpop` 与 `heapreplace` 有什么不同

这两个操作都会在加入一个元素后保持堆大小，但弹出的对象不同：

```python
heap = [2, 5, 8]
print(heapq.heappushpop(heap, 1))  # 1，较小的新元素直接被弹出
print(heap[0])                    # 2

heap = [2, 5, 8]
print(heapq.heapreplace(heap, 1))  # 2，原堆顶一定被替换
print(heap[0])                    # 1
```

`heappushpop` 比较新元素与堆顶，保留较大者；`heapreplace` 则一定移除原堆顶。后者要求堆非空。维护固定大小的候选集时，选择哪一个取决于新元素是否应当参与淘汰比较。

## 第 K 大为什么用最小堆

假设只保留已经读到的数据中最大的 K 个元素。那么，这 K 个元素里最小的那个，正好就是当前第 K 大。最小堆的堆顶可以充当候选集合的门槛。

```python
def kth_largest(nums, k):
    if not 1 <= k <= len(nums):
        raise ValueError("k must be between 1 and len(nums)")

    heap = list(nums[:k])
    heapq.heapify(heap)
    for i in range(k, len(nums)):
        heapq.heappushpop(heap, nums[i])
    return heap[0]


print(kth_largest([3, 2, 1, 5, 6, 4], 2))  # 5
```

这里按元素个数计数，重复值也占名次。空间复杂度为 $O(k)$；时间上，建堆需要 $O(k)$，其余元素各进行一次至多 $O(\log k)$ 的堆操作。一般记为 $O(n\log k)$；包含 $k=1$ 的边界时，可统一写成 $O(n\log(k+1))$。

反过来，维护最小的 K 个元素时，需要能快速移除候选集合中最大的元素，因此适合使用最大堆。

## 最大堆与优先级相同的情况

对数值取负，可以用最小堆模拟最大堆：

```python
heap = []
for value in [8, 2, 5]:
    heapq.heappush(heap, -value)
print(-heapq.heappop(heap))  # 8
```

Python 3.14 起也提供 `heapify_max(heap)`、`heappush_max(heap, value)` 和 `heappop_max(heap)` 等接口。使用在线评测环境时，先确认解释器版本。接口与版本说明见 [Python 官方文档](https://docs.python.org/3/library/heapq.html)。

优先级队列常用 `(priority, value)` 保存条目。元组先比较第一个字段；优先级相同时，还会比较第二个字段。如果第二个字段是不可排序的对象，就可能抛出 `TypeError`。可以加入递增序号，既打破平局，也保留同优先级条目的入队顺序：

```python
from itertools import count

queue = []
sequence = count()
task_a, task_b = object(), object()
heapq.heappush(queue, (1, next(sequence), task_a))
heapq.heappush(queue, (1, next(sequence), task_b))
priority, order, task = heapq.heappop(queue)
assert task is task_a
```

## Dijkstra：堆只负责取出最近的候选

Dijkstra 算法还需要保存当前最短距离，仅当找到更短路径时才入堆，并跳过已经过时的条目。下面假设所有边权非负，图用邻接表表示：

```python
def dijkstra(graph, start):
    distances = {start: 0}
    sequence = count()
    heap = [(0, next(sequence), start)]

    while heap:
        dist, _, node = heapq.heappop(heap)
        if dist != distances[node]:
            continue

        for nxt, weight in graph.get(node, []):
            if weight < 0:
                raise ValueError("Dijkstra requires nonnegative weights")
            candidate = dist + weight
            if candidate < distances.get(nxt, float("inf")):
                distances[nxt] = candidate
                heapq.heappush(heap, (candidate, next(sequence), nxt))

    return distances


graph = {"A": [("B", 4), ("C", 1)], "C": [("B", 2)], "B": [("A", 4)]}
print(dijkstra(graph, "A"))  # {'A': 0, 'B': 3, 'C': 1}
```

如果将所有相邻状态直接入堆，却不检查距离是否改善，遇到环时就可能不断扩展。距离表负责判断哪些候选值得继续，堆负责高效地取出它们，两者缺一不可。

合并多个有序序列、任务调度和数据流中位数也会用到堆。选择它之前，可以先问：我是否只需要快速取得当前最优的候选？若需要完整排序，直接排序往往更合适。
