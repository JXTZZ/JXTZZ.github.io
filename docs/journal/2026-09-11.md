# 从语义动作到对象交互：Show-Harness 与 ORION

今天关注了两篇思路互相呼应的工作：**Show-Harness** 讨论 VLM 与机器人动作空间之间应该使用怎样的接口，**ORION** 则讨论如何从单条人类视频中提取跨 embodiment 的对象交互表示。它们都没有选择最直接的“图像 + 语言 → 连续动作”，而是在感知与控制之间加入结构化中间层。

## Show-Harness：问题可能不只在模型能力

> 论文：*Show-Harness: Just a VLM Agent Can Play Robots*
>
> [项目主页](https://showlab.github.io/Show-Harness/) · [arXiv:2609.10522](https://arxiv.org/abs/2609.10522)

Show-Harness 的核心是一层 **semantic action interface**。VLM 根据观察和指令选择离散、可解释的语义动作单元，再由 embodiment-specific interpreter 将这些动作确定性地转换为机器人底层控制。

```text
VLM
  ↓
semantic actions
  ↓
embodiment-specific interpreter
  ↓
robot actions
```

这篇论文提出了一个很值得继续验证的问题：机器人表现不足，究竟是因为 VLM 不够“聪明”，还是因为模型与连续动作空间之间缺少合适的接口？作者展示了闭源前沿 VLM 的 zero-shot 控制，也展示了对小型开源 VLM 进行低成本微调的可能性。相比直接训练大型 VLA，这条路线把重点放在**动作抽象和接口设计**上。

## ORION：人与机器人共享的是对象交互

> 论文：*Vision-based Manipulation from Single Human Video with Open-World Object Graphs*
>
> [完整阅读笔记](../papers/orion.md) · [本地 PDF](../assets/papers/ORION.pdf)

人类视频没有机器人动作标签，人的手与机械臂也不共享关节空间，因此从视频直接学习动作并不自然。ORION 的判断是：人与机器人完成同一任务时，真正共享的是 **object interaction**，例如操作哪个物体、在哪里抓取、对象之间的接触关系怎样变化，以及物体以什么轨迹到达子目标。

ORION 将这些信息组织成一串 **Open-World Object Graphs（OOGs）**。图中的 object node 表示任务物体，grasp node 表示交互点与夹爪状态，point node 保存三维关键点或 6-DoF 位姿轨迹，边则描述接触与归属关系。部署时，机器人根据当前场景匹配 OOG 阶段，把演示中的对象轨迹 warp 到新的起终点，再优化为末端 SE\(3\) 动作。

## 三种中间表示的对照

|工作|输入|中间表示|如何落到机器人动作|
|---|---|---|---|
|Show-Harness|机器人观察 + 语言指令|离散 semantic actions|本体解释器转换为局部控制|
|SPOT|少量 RGB-D 人类演示|目标相对的 6D object pose trajectory|结合抓持关系转换为末端轨迹|
|ORION|单条 RGB 或 RGB-D 视频|OOG：对象、接触、抓取与运动轨迹|图匹配 + 轨迹 warping + SE\(3\) 优化|

共同思路可以概括为：

```text
视觉／语言／人类演示
  ↓
与 embodiment 相对解耦的中间表示
  ↓
本体相关的动作解释与控制
```

中间表示越紧凑，跨本体迁移越容易，但也越可能漏掉任务细节；表示越丰富，pipeline 和感知依赖就越复杂。SPOT 的位姿轨迹简洁，却较依赖 RGB-D 与可靠位姿；ORION 加入对象图、接触关系和抓取信息，也相应引入更多视觉模块；Show-Harness 的 semantic actions 更接近 VLM 的推理空间，但动作词表的粒度与解释器能力会决定控制上限。

## RGB-only 视频如何恢复三维轨迹

ORION 最吸引我的一点，是普通 RGB 视频也能作为演示来源。它不是跳过三维信息，而是通过估计补齐三维几何：

```text
RGB 视频
  ↓
单目深度估计 + 对象网格生成
  ↓
在中值深度 ±0.15 m 内搜索多组位姿假设
  ↓
FoundationPose refinement
  ↓
6-DoF 对象位姿轨迹
```

因此，只有一段 YouTube 视频时也有可能构造 OOG，但代价是更长的感知链路，以及单目深度、网格尺度和位姿跟踪带来的误差。**RGB-only 降低了数据采集门槛，并没有消除对可靠三维表示的需求。**

## 可以继续尝试的方向

1. **从小型开源 VLM 开始验证接口。** 先设计有限、可解释的 semantic action set，用监督微调验证模型能否稳定选择动作；闭环执行可靠后，再考虑引入仿真强化学习，而不是一开始就让模型回归连续控制量。
2. **把 semantic action 与 OOG 结合。** VLM 负责选择“抓取目标、移动、对齐、释放”等高层语义动作，OOG 提供对象、接触关系和几何子目标，底层控制器负责可达性与精确执行。
3. **比较不同 representation 的信息边界。** 6D pose trajectory、OOG 和 action chunk 分别保留了多少任务信息？可以在相同演示与控制器下替换中间表示，观察空间泛化、长时序执行和失败恢复的变化。
4. **面向 RGB 视频扩展 SPOT。** SPOT 依赖 RGB-D 演示，因此难以直接利用规模更大的互联网 RGB 视频；ORION 则通过单目深度估计、对象网格重建与位姿跟踪，将 RGB-only 演示转化为 6-DoF 对象轨迹，但较长的感知链路也容易逐级累积误差。一个值得验证的方向，是学习从 RGB 观测稳定地恢复 6D pose trajectory：由 VLM 负责对象识别与任务语义理解，再由带有显式几何约束的专门模块估计连续位姿，从而减少对复杂流水线的依赖。

## 今日结论

从人类视频到机器人动作，真正困难的往往不是缺少一个更大的模型，而是缺少一个既保留任务结构、又能跨 embodiment 复用的接口。Show-Harness 从语义动作出发，SPOT 从物体位姿轨迹出发，ORION 从开放世界对象图出发；三者都在回答同一个问题：**模型理解了任务之后，应该用什么表示把“理解”可靠地交给机器人？**
