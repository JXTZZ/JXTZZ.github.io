# Show-Harness：VLM 如何驱动机器人

> 论文：*Show-Harness: Just a VLM Agent Can Play Robots*
>
> [项目主页](https://showlab.github.io/Show-Harness/) · [arXiv:2609.10522](https://arxiv.org/abs/2609.10522)

## 一句话理解

Show-Harness 没有让视觉语言模型（VLM）直接预测连续的底层控制量，而是在模型意图与具体机器人动作之间加入一层紧凑的**语义动作接口**：VLM 负责观察、推理并选择动作，面向不同机器人的解释器再将这些语义动作确定性地落到局部控制上。

换句话说，这项工作的重点不只是“换一个更强的模型”，而是重新设计模型与机器人沟通的方式。

## 核心设计

1. **语义动作单元**：系统向 VLM 提供一组离散、可推理的动作，让模型继续在自己擅长的语义空间中做决策。
2. **具身解释器**：不同机器人使用各自的解释器，把同一语义动作转换为本体相关的局部运动。
3. **统一接口**：同一套 Harness 既可以让闭源前沿 VLM 直接进行零样本控制，也可以通过少量微调部署开源小模型。
4. **GUMI**：论文还设计了 GUI Manipulation Interface，将相同的语义动作空间用于示范采集，使人和 Agent 都能通过图形界面“操作”不同机器人。

## 为什么值得关注

这篇论文把重点放在“接口”而非单纯增加模型容量上。按照作者在摘要中的报告，Show-Harness 可在任务、机器人本体与环境之间实现泛化，并优于若干 Agent 与 VLA 基线。这个方向很吸引人：如果接口设计得足够好，基础 VLM 已有的视觉与语义能力或许可以更低成本地迁移到机器人控制中。

但这也把新的压力放到了语义动作空间和解释器上：动作粒度是否足够细、解释器能否跨本体复用、闭环频率是否满足实时控制，都会直接影响系统能力的上限。
