## 作业概述

用 Factory 的 Agent 就绪度报告，评估三个开源仓库，记录发现，再解释它们呈现的规律。每个仓库只需一条命令就能生成报告；真正要下功夫的，是**把三份报告放在一起比较**，对仓库的不足提出有依据的判断。

### 学习目标

- **评估**陌生仓库，使用统一的 Agent 就绪度框架。
- **比较**不同仓库的结果，区分共性问题与个别情况。
- **归纳**三个样本的发现，提出经得起推敲的结论。

## 参考资料

- **[Factory：Agent Readiness](https://factory.ai/news/agent-readiness)**：介绍评估框架、八个维度，以及五个成熟度等级。八个维度分别是：风格与校验、构建系统、测试、文档、开发环境、代码质量、可观测性、安全与治理。
- **[Droid](https://factory.ai/)**：Factory 的命令行工具，用它生成报告。

## 选择仓库

从[第 4 周的列表](../week4/assignment.md)中选**三个**，也可以自行选择。尽量让它们在语言、规模和项目历史上有所不同，否则第二部分会缺少可分析的差异。

## 环境准备

**前提：安装 Droid CLI。** 安装命令见 [Droid 快速入门](https://docs.factory.ai/cli/getting-started/quickstart)。

## 第一部分：生成报告（40 分）

克隆每个仓库，在仓库根目录启动 Droid 并运行 `/readiness-report`。它会自动评估八个维度下的 60 多项标准，给出成熟度等级、各项是否通过的明细，以及改进建议。

每个仓库都要记录：

- 成熟度等级，以及哪些未达标项阻碍它进入下一等级。
- 各维度得分。
- 按维度分组的未通过项目。
- 报告本身给出的首要改进建议。

同时附上原始输出。不过，重点仍是整理后的结果：只有把三份报告整理成便于比较的格式，才能完成第二部分。

## 第二部分：仓库的不足在哪里（60 分）

根据你的数据，回答以下问题：

- **哪些维度未通过最多？** 三个仓库是否有相同问题，还是某个仓库独有？
- **什么能解释这种规律？** 检验几个直观猜想：项目历史、语言、规模，以及个人维护还是企业支持。说明这三个仓库能支持哪些判断，又不足以证明什么。
- **成本最低、收益最大的改进是什么？** 为每个仓库选一项最能改善 Agent 工作成功率的修改，并解释为什么选它，而不是报告给出的首要建议。
- **框架本身有什么不足？** 例如，某个维度的实际重要性低于其权重暗示的重要性，某项标准不适用于这类仓库，或遗漏了明显影响 Agent 的因素。

三个仓库只是很小的样本，结论不要超出它们能支持的范围。

## 提交内容

在 `week5/` 中提交完成的 `writeup.md`，包含记录的结果、分析，以及每个仓库的报告原始输出。

## 评分标准（共 100 分）

| 部分 | 分值 | 满分要求 |
| --- | --- | --- |
| 一、报告 | 40 | 完成三个仓库的评估；结果记录完整，格式便于比较 |
| 二、分析 | 60 | 从数据找出并解释规律；说明各仓库改进方案的理由；评价框架局限；结论范围与样本相符 |
