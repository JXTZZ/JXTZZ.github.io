## 引言

如果让我们从零编写一个助手，最直接的办法大概是整理知识，再规定遇到某种情况该怎样回答。这条路线确实做成过不少有价值的系统，但规则越写越多，现实里的变化仍然难以写尽。

本章沿着几次重要转变展开：从手工表示知识，到组织不同能力，再到从数据和交互中学习。现代智能体的许多组件，都能在这些早期探索中找到线索。

<a id="section-2-1"></a>

## 2.1　把知识写成符号和规则

符号主义（Symbolism）希望用明确的表示描述世界，再依照规则推导结论。例如，把物体的位置、大小和相互关系写成事实，规划程序就可以考虑先移动哪个物体。

物理符号系统假说为这条路线提供了重要理论背景。它认为，组织得当、规模足够的物理符号系统具备产生通用智能的手段；反过来，任何通用智能系统本质上也应能作这样的解释。这是一项强假说，并不是说任意规则程序都已经具有通用智能。

<a id="section-2-1-1"></a>

### 2.1.1　专家系统怎样工作

专家系统将领域知识与推理过程分开。知识库保存事实和规则，推理机决定当前能使用哪些规则，用户界面则负责收集问题和显示结果。

正向推理从已有事实出发，寻找能够推出的新结论；反向推理从待验证的目标出发，逐步询问还需要哪些证据。前者像顺着线索往前查，后者像先提出假设，再核实成立条件。

MYCIN 是本章的重要例子。它围绕特定感染问题提供辅助判断和治疗建议，并用置信因子表达不确定性。这个案例说明，精心整理的专业知识能够支持较复杂的推理；但在有限病例上的表现，不能直接等同于广泛临床应用的效果。

<a id="section-2-1-2"></a>

### 2.1.2　SHRDLU 与积木世界

SHRDLU 把语言理解、规划和状态记录接在一起。用户要求移动一块积木时，程序不仅需要识别对象，还要判断它是否被压住，再安排必要的中间动作。

这个例子的重要之处在于各模块的配合。理解一句话，需要知道世界里有哪些对象；规划下一步，又依赖语言中表达的目标。系统还可以利用已有记录回答后续问题。

不过，积木世界的对象和规则都受到严格限制。到了开放环境，常识、例外和模糊表达会迅速增加。专家未必能说清自己的全部经验，工程师也难以把知识逐条录入，这便形成了知识获取瓶颈。

<a id="section-2-1-3"></a>

### 2.1.3　用一条规则理解知识库与推理机

不妨用设备排障代替复杂专业问题。假设知识库写着：“电源接通并且指示灯不亮时，检查供电模块。”用户提供的“电源已接通”只是一个事实，还缺少指示灯状态。推理机需要决定继续询问什么，不能直接跳到最终结论。

如果从现有状态出发，逐步寻找所有适用规则，就是正向推理；如果先检查“是否需要更换供电模块”这个候选结论，再追问各项成立条件，就是反向推理。两种方式的差别在搜索方向，不在知识是否由人编写。

知识库与推理机分离，使同一套推理程序能够用于不同领域。但换领域仍然要重新组织事实、规则和术语，不能只把文件名换掉。术语是否明确、条件是否互相冲突，会直接影响结果。

<a id="section-2-1-4"></a>

### 2.1.4　为什么小世界能够成功，开放世界却更困难

积木世界里的对象数量有限，颜色、位置、支撑关系都有明确含义。程序可以假设规则已经描述了大部分相关情况。真实环境则可能出现透明物体、破损器件、隐含意图和语言省略，许多前提并未直接给出。

另一个困难是描述行动以后哪些东西发生了变化。移动一个物体，不应让其他物体的颜色跟着改变；但哪些关系保持不变、哪些关系需要更新，必须有相应表示。这是把直觉常识写成形式系统时会遇到的问题。

因此，符号方法的难点并不只是规则“不够多”。还包括表示是否适合、怎样处理默认与例外，以及推理能否在有限时间内完成。理解这些限制，有助于解释后续为什么转向学习，而不是简单评价某一代系统不够聪明。

<a id="section-2-2"></a>

## 2.2　示例：ELIZA 怎样让对话继续

ELIZA 的经典脚本通过关键词与句式转换，引导用户继续表达。它不需要先建立完整的世界知识，就能生成看起来与上句话有关的回应。

**示例 2.1　从陈述到追问**

```text
输入：我需要一些帮助。
处理：识别“我需要……”，捕获后面的内容。
输出：你希望这些帮助解决什么问题？
```

实现时，程序先匹配规则，提取片段，必要时转换代词，再将片段放进回答模板。原文使用正则表达式展示这一过程，规则可以按优先顺序依次尝试。

方法简单，也很容易看出边界。同样的意思换一种说法，可能无法匹配；加入否定词后，表面相似的句子可能表达相反意思。若每轮只处理当前句子，程序也无法自然地引用先前信息。

因此，对话连贯的表面效果与实际理解能力，需要分别判断。这个小程序把符号方法的优势和局限都展示得很清楚：局部行为容易规定，开放域覆盖却很难维护。

<a id="section-2-2-1"></a>

### 2.2.1　一次模式匹配的内部步骤

简化版 ELIZA 可以分成四项工作：选择规则、提取片段、转换表达、放入模板。若输入“我需要帮助整理项目”，程序识别需求句式，捕获“帮助整理项目”，再用追问模板回应。

代词转换解决的是表述视角。例如，将用户片段中的“我的”换成回应中的“你的”，能让句子读起来较自然。这一步只是按规则替换，并没有建立关于人物或意图的完整理解。

```text
输入句子
  → 检查哪条模式先命中
  → 提取模式中的可变部分
  → 按规则调整代词等表述
  → 填入回答模板
  → 若无匹配，使用通用追问
```

通用规则通常放在最后，否则它会先匹配所有输入，使后面的具体规则永远没有机会执行。规则顺序因而已经是一个简单的决策策略。

<a id="section-2-2-2"></a>

### 2.2.2　从具体例子观察规则的覆盖问题

“我想换一份工作”和“现在的岗位让我很累”可能围绕同一个问题，却未必命中相同模式。“我并不需要帮助”又可能含有需求关键词，但表达的是相反意思。只检查词是否出现，难以稳定区分这些情况。

给规则增加例外可以修正一个案例，却可能影响另一个。工作、情绪、否定和前文指代交织以后，开发者需要同时考虑内容与优先级。问题逐渐从写一句回应，变成维护一张不断扩大的关系网。

这也是 ELIZA 的教学价值：它让我们直接看到自然回应可以怎样产生，也让我们看到这种回应依赖了哪些人为安排。评价对话系统时，应该继续检查换说法、换背景和多轮互动，而不只展示一段顺畅对话。

<a id="section-2-3"></a>

## 2.3　让许多简单过程协同工作

明斯基的“心智社会”（The Society of Mind）把关注点放在能力如何组合。一个过程未必要懂得整个任务；它可以只做很小的一件事，再由其他过程配合。

在搭积木的例子中，较高层的过程不断要求添加积木；下面再分成寻找、抓取和放置。负责抓握的过程不需要知道什么是塔，负责重复添加的过程也不需要知道怎样控制手指。

```text
搭建积木塔
  └─ 反复添加积木
      ├─ 找到合适积木
      ├─ 伸手并抓住
      └─ 放到塔顶
```

这种看法启发了分布式智能和多智能体研究：可以把能力组织起来，而不必把所有知识放进一个统一的推理核心。不过，分工仍需要协调；一个不可替代的底层能力失效，也会阻断依赖它的任务。

今天的软件框架有时采用协调者和固定流程，有时允许角色自由交换信息。它们与心智社会共享分工的思路，具体结构却不必完全相同。

<a id="section-2-3-1"></a>

### 2.3.1　协作中的激活、抑制与任务依赖

搭塔时，找到积木后才应抓取，抓稳以后才应放置。负责不同动作的过程，需要通过信号或共享状态协调，而不是同时执行各自认为合适的动作。

激活可以理解为让相关过程参与，抑制则帮助暂时阻止不合适的过程。比如抓取尚未完成时，放置过程就不应把对象当成已经在手中。这些局部约定共同维持整体行为。

层次结构也不等于存在一个知道全部细节的全能控制器。高层可以只负责重复和选择，下层负责具体动作；但底层能力仍有依赖。若抓握无法完成，高层需要收到失败或未完成信息，才能作出有意义的下一步选择。

现代多智能体应用也有类似要求：研究员的结果要明确交给写作者，执行器要知道输入是否齐全。把组件叫作“智能体”之前，先说明它们怎样交换状态，常常更有帮助。

<a id="section-2-4"></a>

## 2.4　从设计知识，到学习能力

<a id="section-2-4-1"></a>

### 2.4.1　联结主义：在参数中学习模式

联结主义（Connectionism）不要求把每条知识都写成人类可读的规则。神经网络通过训练调整连接权重，使输出逐渐接近目标。

知识由此分布在大量参数中。面对复杂图像或语言，这种方式能够学习人工规则难以覆盖的模式；代价是内部表示不再像知识库那样容易逐条检查。

<a id="section-2-4-2"></a>

### 2.4.2　强化学习：让行动接受结果检验

强化学习关注选择与后果。智能体观察状态、执行动作、获得反馈，并调整策略，使未来的累计收益更好。

下棋很适合说明这一点。某步棋眼前可能没有收益，却会影响后续局面。训练必须把最终结果与先前行动联系起来。AlphaGo 结合过人类棋谱学习、自我对弈与搜索，不能将整个系统简单归为一种训练方法。

<a id="section-2-4-3"></a>

### 2.4.3　预训练：先积累通用能力

在大规模数据上进行预训练，可以让模型先学习广泛的语言模式与知识，再适应具体任务。自监督目标从数据本身构造学习信号，例如预测下一个词元，减少了逐条人工编写知识的需求。

预训练缓解了知识获取的规模问题，也带来新问题：数据可能错误，参数中的知识难以追溯，更新也不如修改一条记录直接。能学习很多内容，并不意味着每次回答都有可靠依据。

<a id="section-2-4-4"></a>

### 2.4.4　三类学习信号怎样区分

监督学习从输入与示范输出的对应关系中学习；自监督学习从数据本身构造目标，例如隐藏或预测其中一部分；强化学习则利用行动结果的评价调整策略。

| 学习情境 | 提供了什么 | 系统需要学什么 |
| --- | --- | --- |
| 看人类棋谱 | 局面与下一步落子。 | 在类似局面下选择示范动作。 |
| 预测文本后续 | 前文与真实后续词元。 | 建立语言序列的概率关系。 |
| 自我对弈 | 行动轨迹与最后胜负。 | 哪些选择更有利于长期获胜。 |

数据形式可以转换，方法也可以组合。AlphaGo 先利用棋谱获得基础能力，再通过自我对弈等方式改进，就是一个典型例子。它说明学习路线之间可以衔接，而不是必须三选一。

<a id="section-2-4-5"></a>

### 2.4.5　训练完成以后，智能体怎样继续适应

预训练提供广泛基础，微调改变任务行为，上下文则提供眼前的要求与资料。一个已经训练好的模型，还可以依靠查询工具取得新信息，依靠外部记忆保留用户偏好。

例如，新景点开放后，助手可以搜索资料并在这次规划中使用，不必立即重新训练整个模型。如果希望许多任务中都更稳定地遵守某种格式，则可能需要数据与训练。信息更新与行为训练，因此可以走不同路径。

这些方法也各有代价。检索需要找到可靠资料，记忆需要管理过时信息，训练需要评估是否真正改进。学习并没有取消工程设计，而是改变了能力获得与验证的方式。

<a id="section-2-5"></a>

## 2.5　现代智能体把这些思路接到一起

现代 LLM 智能体通常同时包含模型、规划、记忆、工具和执行控制。模型帮助理解要求并提出行动，记忆保留已有信息，工具提供外部能力，控制程序保证动作被正确执行并接收结果。

从这个角度看，历史没有简单地淘汰所有旧方法。明确规则仍适合检查边界，神经网络擅长处理复杂输入，交互反馈帮助改进决策，模块分工则让系统更容易组合。

<a id="section-2-5-1"></a>

### 2.5.1　用同一个问题比较几代方案

仍以旅行规划为例。规则系统可以按天气和预算匹配预设路线；学习系统能够处理更灵活的用户表达；加入工具后，可以查询当前资料；增加任务状态与记忆后，又能接收后续修改。

这些进步来自不同部分。用户说得自然，依赖语言处理；天气真实，依赖外部查询；日程前后一致，依赖状态和验证。把所有改善都归为模型规模增加，会遗漏许多关键设计。

因此，阅读历史时可以反复追问：新方法减少了哪种人工工作，新增了什么能力，又把困难转移到了哪里？沿着这个问题继续学习，会比只记住项目年代更容易理解现代系统。

下一章将暂时聚焦其中最受关注的组件：大语言模型。它如何处理文本，又为什么既有广泛能力，也会生成错误内容？
